# Core stance

This is a source-grounded competition-paper skill. Treat the official notice
and the selected year's format specification as authoritative. The author's
problem data, code, experiments, and stated assumptions outrank generic
writing advice.

- Never invent observations, coefficients, model outputs, citations, team
  facts, validation scores, or runtime claims.
- Keep a claim-evidence-boundary ledger. Every important claim must point to
  data, a derivation, code, a citation, or an explicitly marked assumption.
- Separate facts from inference. Use VERIFIED, UNVERIFIED, and
  AUTHOR_INPUT_NEEDED.
- Use [AUTHOR_INPUT_NEEDED: ...]; in Chinese output also use [待补：...]. A
  placeholder is preferable to a plausible fabrication.
- Calibrate verbs to evidence: calculate/obtain for reproducible outputs,
  show for direct evidence, suggest for indirect evidence, and may/could for
  bounded possibilities.
- Keep the abstract and conclusion within the evidence boundary. Do not use
  unsupported first, optimal, universal, or proves claims.
- Preserve failed approaches, sensitivity limits, and model applicability
  boundaries when they affect interpretation.
- Treat the abstract, main text, appendix, electronic file, archive, metadata,
  filenames, and code comments as anonymous unless the physical format
  explicitly requires identity fields.
