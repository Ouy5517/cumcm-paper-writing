# Complete CUMCM workflow

Read the problem and available attachments; resume verified work rather than
restarting it. Build one row per requested output using
`references/problem-coverage.md`. A problem may require several model families
and may have parameter-only or purely analytical parts.

Load the next relevant task fragment in this order, per subquestion:
`understand` → `prepare-inputs` → `formulate` → `solve` → `validate` →
the requested writing scope → requested delivery / `preflight` / `submission-package`.
Choose `draft-section` for a requested results paragraph or section, `draft-paper`
only for a full manuscript, and no drafting task when only calculation is requested.
Do not eagerly load all task or model fragments. `plan` is a writing plan;
`understand` is the mathematical problem intake.

Move forward when the current stage supplies what the next stage needs:
requirements mapped; usable inputs or explicit bounds; defined model; executed
calculation or derivation; claim-appropriate checks; consistent prose; inspected
deliverable. Failed validation returns only affected parts to the earlier stage.
If one input is missing, advance independent questions and label conditional
results; do not quietly substitute an easier target.

Use the available deadline and compute budget to prioritize required outputs,
then credibility checks, then optional improvements. If no budget is specified,
start with a tractable baseline. Add complexity only to address a concrete
deficiency. Stop when the requested outputs and appropriate validation are
complete, or document the unresolved limit when resources/input prevent it.

For matching case structures load `references/distilled-playbooks.md`. Cases
guide checks; never reuse a previous answer, fixed algorithm or award claim as
proof. End with separate coverage, science, rendering, rules and team-review
statuses. A complete workflow does not guarantee an optimal solution or award.
