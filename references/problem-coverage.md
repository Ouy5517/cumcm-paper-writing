# CUMCM problem coverage

Create one row per output requested by the selected CUMCM problem:
question ID | original requirement | needed inputs | model/output |
code/result location | status | missing evidence and consequence.

For a full modeling workflow also record each output's goal (estimate, predict,
explain, evaluate or decide), input modality, upstream dependencies, current
stage, acceptance check, model family, and evidence/validation location. These
can be additional columns or compact notes in the same record. Do not create
separate mandatory configuration files. Use stages from the task axis rather
than a second global router; different subquestions can be at different stages.

Update state when artifacts or checks change. `complete` means the requested
output and relevant checks exist, not that a script or section heading exists.
Record human review of AI-assisted work independently when formal competition
rules apply; never self-attest for participants.
When the required output spans dates, entities or operating scenarios, record
that grid and reconcile it with actual result rows. A heading or aggregate score
does not establish coverage of the requested horizon or every scenario.

Statuses: complete / partial / not-identifiable / not-started / not-applicable.
A conceptual mechanism interface is not an executed rule comparison. Frequencies
are not automatically personalized predictions. Complete all independently
answerable tasks even if another task lacks data. Explain conditional estimates
or bounds without replacing the original target with an easier question.
Map abstract and conclusion to this matrix. Report scientific completion
separately from formatting success.
