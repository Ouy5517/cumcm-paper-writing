# Paper structure reference

Use this reference for a full-paper outline, not for every short edit.

1. Abstract page: problem focus, method for each subproblem, decisive
   quantitative results, robustness/limitations, and keywords. Keep it to one
   page and do not introduce numbers that are absent from the result ledger.
2. Problem restatement: preserve the task's meaning without copying
   unnecessary narrative.
3. Assumptions and notation: state only assumptions used by the model; define
   symbols, units, indices, and data transformations.
4. Model formulation: objective, decision variables, constraints, equations,
   parameter sources, and interpretation.
5. Solution and algorithm: derivation, solver/algorithm, initialization,
   stopping rule, complexity or convergence evidence when relevant.
6. Results: answer subproblems in order; use tables/figures with captions and
   units; connect each result to the method that produced it.
7. Validation and sensitivity: compare with baselines or checks, perturb key
   assumptions/parameters, and state what is not validated.
8. Conclusions and limitations: answer the problem, summarize bounded
   findings, and state applicability limits.
9. References: cite all external data, definitions, methods, and software
   documentation actually used.
10. Appendix: file list, complete runnable source programs, reproducibility
    notes, and the exact no-program/no-support declaration when applicable.

Do not add a table of contents. Keep narrative, notation, units, result values,
and conclusion wording consistent across the body, appendix, and electronic
package.
