# Paper architecture

Adapt to the selected CUMCM problem. A useful reasoning chain is problem -> data
and assumptions -> notation -> model -> solution -> results -> validation ->
limitations and conclusion. These need not be separate chapters. Keep each
subproblem's method and results close; remove repeated arguments and tables.
Write the summary after results stabilize. Apply the selected-year verified
CUMCM official notice, submission package, and supplied template to front
matter, disclosure, references, and appendix placement.
Use code-appendix.md for concise source presentation; retain complete engineering
files separately where permitted. Never impose a universal appendix page limit.
For results allocation, full-paper compression, result placement, or repeated
tables, load main-text-discipline.md and apply its evidence destinations.

## Table rhythm

Treat a table as part of the argument, not as a page-filling tile. Do not create
a 2-by-2 montage from four independent tables, and do not leave four tables as
an uninterrupted table wall. Keep each table close to the method, result, or
subproblem it supports. Normally place no more than two tables consecutively;
add interpretation before the next table so the reader knows why the values
matter. Split oversized tables only along meaningful semantic groups, and keep
each resulting table independently understandable.

## Selective emphasis

Use bold text only for key conclusions, decisive indicators, core objectives or
constraints, and important risks or applicability boundaries. Keep the bold span
short, normally a phrase or one sentence. Do not bold whole paragraphs, repeat a
heading's emphasis in the opening sentence, emphasize routine transitions, or
mechanically bold every table takeaway. Emphasis supports the reasoning hierarchy;
it does not replace one.
