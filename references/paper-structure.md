# Paper structure reference

Use this reference for a full-paper outline, not for every short edit.

1. Abstract page: problem focus, method for each subproblem, decisive
   quantitative results, robustness/limitations, and keywords. Keep it to one
   page and do not introduce numbers that are absent from the result ledger.
2. Problem restatement: preserve the task's meaning without copying
   unnecessary narrative.
3. Problem analysis: decompose each requested question, state what the data
   can identify, and connect each subproblem to a model or descriptive method.
4. Assumptions and notation: state only assumptions used by the model; define
   symbols, units, indices, and data transformations.
5. Model formulation: objective, decision variables, constraints, equations,
   parameter sources, and interpretation.
6. Solution and algorithm: derivation, solver/algorithm, initialization,
   stopping rule, complexity or convergence evidence when relevant.
7. Results: answer subproblems in order. Put charts beside the claim they
   support; state units, denominator, sample size/scope, and whether marks are
   observations, fitted values, or extrapolations. Use tables for exact lookup.
8. Validation and sensitivity: compare with baselines or checks, perturb key
   assumptions/parameters, and state what is not validated.
9. Model evaluation: summarize strengths, weaknesses, applicability, and what
   additional inputs are needed for mechanism or policy claims.
10. Conclusions and limitations: answer the problem, summarize bounded
   findings, and state applicability limits.
11. AI-use statement: place the current-year required declaration immediately
    before references; keep detailed usage records in support when required.
12. References: cite all external data, definitions, methods, and software
   documentation actually used.
13. Appendix: file list, complete runnable source programs, reproducibility
    notes, and the exact no-program/no-support declaration when applicable.

Do not add a table of contents. Keep narrative, notation, units, result values,
and conclusion wording consistent across the body, appendix, and electronic
package.
